# Nowledge Mem Maintenance

Maintain knowledge quality in a local or cloud runtime. Preserve useful history.
This skill complements the plugin's ordinary memory skills.

## Start the review

1. Read the current Context Bundle. Retrieve it through MCP when possible.
   A successful live context read also checks the connection.
2. Preserve the configured owner, AI identity, Space, and retrieval policy.
   A temporary task identifier does not select a new AI identity.
3. Confirm the requested scope. A feed review does not authorize a whole-store cleanup.
4. Search memories or threads for relevant prior decisions and evidence.
   Read full bodies for the records you use. Search previews are not complete evidence.
5. Inspect the available tools and their current schemas. Names and fields can differ by deployment.

Prefer MCP. Use `nmem` only when this runtime provides the CLI and a valid connection.
Check installed help before using a command. If a needed tool is absent, report the blocked operation.
Continue useful reads within scope. Do not use a different endpoint to bypass a guarded action.
A failed connection or degraded search cannot prove that evidence is absent.

## Review evolution before content

For conflicts, stale flags, or version repair, read [evolution-review.md](references/evolution-review.md).
Use this order:

**Scope and connection → full bodies and EVOLVES topology → current successors and sources → claim classification → minimum change → required preview and exact-plan apply → verification → review closure.**

- A flagged memory can already have a valid replacement. Preserve correct historical bodies.
- Inspect direct edges and branches as well as the chain summary.
- Choose progression, validation, or an independent Memory Link from the claims' meaning.
- A recording error can need an in-place correction. A genuine change can need a successor.
- Timeline graph decisions require a displayed plan and the person's review of that exact plan.
- Replacement, review closure, crystal confirmation, trust, and archive are separate operations.
  Do not archive a historical memory merely because it was replaced.

## Verify completion

Read the changed bodies, graph edges, current successors, lifecycle, and review receipts.
Check inherited labels against the active owner's rules.
Report resolved, previously resolved, expired, blocked, and untouched items separately.

Follow every supported page before claiming complete coverage.
If a tool has only a limit and no complete-coverage signal, report the visible bounded set.
Do not advance an offset through a pending list while mutations shrink that list.
Collect the candidate IDs first, or use a supported stable cursor.

Completion means the requested set has verified outcomes.
An empty feed does not prove knowledge quality.
Unrelated cleanup or crystal work can remain pending.
